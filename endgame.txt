The generalist idea of this project is to let me just type whatever I want in, every time I get an idea, and be able to easily find it later by thinking of something adjacent or the day it’s happening or anything else at all. The secondary goal is for it to look very beautiful and be relatively low compute weight over time, encouraging users to have it open on another monitor.


Key technical challenges to explore:


The impedance mismatch between "just type whatever" and structured storage

The embedding generation pipeline and its performance implications

The "headspace" interface as primary organizing metaphor

The tension between flexibility and searchability


The core tension in your system is between "just type whatever" and "find it later through any mental pathway." This isn't a UI problem - it's a fundamental indexing challenge.


The Real Problem: Lazy vs Eager Processing

When you type "meeting with sarah next tuesday about the vector db migration", your system needs to decide immediately:


Extract "next tuesday" and convert to actual date?

Generate embedding now or later?

Parse "sarah" as entity or leave as text?

Tag "vector db" as technical topic?

The naive approach says "process everything immediately" but that creates input lag. Type, wait 300ms for embedding generation, another 50ms for NLP parsing. Death by latency.

The smarter approach: Write-through cache with async enrichment. You type, it saves raw text instantly with just a timestamp. Background workers handle:


Embedding generation (batch these - most models prefer batches anyway)

Date extraction (surprisingly expensive with good accuracy)

Entity recognition (people, projects, systems)

The Interface Isn't What You Think

You described clicking clusters to see snippets. But the graph isn't really about dates - it's about temporal locality as a memory cue. You don't remember "November 15th" - you remember "that Tuesday when I was debugging the auth system."

This suggests the interface needs context layers:


What project was active that week?

What problems were you solving?

What external events happened? (deployments, meetings, incidents)

The technical implication: your nodes need ambient context captured automatically. When you type a snippet, the system should know what browser tabs are open, what project directory you're in, maybe even time of day patterns.


Vector Search's Dirty Secret

Embeddings are terrible at specifics. Search for "that bug in the authentication middleware" and you'll get every mention of bugs, authentication, and middleware, but probably not the specific incident you want.

The solution isn't better embeddings - it's hybrid retrieval:


Vector search gets you the semantic neighborhood

Keyword search on that neighborhood for specific terms

Temporal filtering based on your memory's rough timeline

Technically, this means indexing everything three ways:


Full-text search index (PostgreSQL's tsvector or SQLite's FTS5)

Vector embeddings (768-1536 dimensions typically)

Temporal index with fuzzy date matching

The Storage Decision That Actually Matters

Forget SQL vs NoSQL. The real question: mutable or immutable entries?

Immutable (append-only log):


Every edit creates a new version

Natural audit trail

Can reconstruct any past state

Storage grows linearly with edits

Mutable (update in place):


Simpler mental model

Less storage

Lose history unless explicitly versioned

Cache invalidation nightmare

I'd argue for immutable with a twist: event sourcing lite. Every input is an event:


TextEntered

DateExtracted

EmbeddingGenerated

UserCorrectedDate

Your "nodes" are materialized views over these events. This lets you retroactively improve parsing - reprocess old events with better NLP models.

The Critical Performance Bottleneck

It's not the database. It's the embedding generation.

A good text embedding model (say, text-embedding-ada-002 or local BERT variant) takes 50-200ms per chunk. You type 50 snippets a day? That's 10 seconds of processing.

Options:


Batch nightly - everything gets embedded at 2am

Progressive enhancement - immediate keyword search, semantic search appears later

Local small model - 20ms inference but worse quality

Selective embedding - only embed entries over 20 words

The practical choice: Progressive enhancement with a local model for immediate feedback, upgraded to a better model async.


Why This Fails (And How to Prevent It)

Systems like this fail when:


Input friction exceeds thought speed

Retrieval requires remembering how you stored it

The organizational overhead grows over time

The technical antibodies:


10ms input latency ceiling - anything slower breaks flow

Zero required taxonomy - tags/folders are optional enhancement

Automatic decay - old entries gradually become archived unless accessed

The decay point is crucial: entries should have a "relevance half-life." Not deleted, but moved to cold storage. This keeps working set manageable while preserving everything.

The Universal Input Handler

#!/usr/bin/env python3

import sys, os, datetime, subprocess, mimetypes

from pathlib import Path


def process_input(data, filename=None):

timestamp = datetime.datetime.now()

base_path = Path.home() / "brain" / f"{timestamp:%Y/%m/%d}"

base_path.mkdir(parents=True, exist_ok=True)

# Microsecond timestamp for uniqueness

prefix = f"{timestamp:%H%M.%f}"[:12]

# Detect input type

if filename:

mime = mimetypes.guess_type(filename)[0]

else:

mime = "text/plain"

# Process based on type

if mime and mime.startswith("image/"):

return handle_image(data, prefix, base_path)

elif mime and mime.startswith("audio/"):

return handle_audio(data, prefix, base_path)

elif filename and filename.endswith(".pdf"):

return handle_pdf(data, prefix, base_path)

elif filename and filename.endswith(".docx"):

return handle_docx(data, prefix, base_path)

elif filename and filename.endswith(".diff"):

return handle_diff(data, prefix, base_path)

else:

return handle_text(data, prefix, base_path)


def handle_image(data, prefix, base_path):

# Save original

orig_file = base_path / f"{prefix}-image.png"

orig_file.write_bytes(data)

# Extract text (OCR + image-to-text description)

text = subprocess.run(["tesseract", str(orig_file), "-"],

capture_output=True, text=True).stdout

# If minimal text, try image captioning

if len(text.strip()) < 20:

# Use local CLIP or BLIP model

text += "\n" + generate_image_description(orig_file)

# Save searchable text

text_file = base_path / f"{prefix}-image.txt"

text_file.write_text(f"IMAGE: {orig_file.name}\n{text}")

return text_file


def handle_audio(data, prefix, base_path):

# Save original

orig_file = base_path / f"{prefix}-audio.m4a"

orig_file.write_bytes(data)

# Transcribe with whisper.cpp (fast, local)

text = subprocess.run(["whisper", str(orig_file)],

capture_output=True, text=True).stdout

# Save searchable text

text_file = base_path / f"{prefix}-audio.txt"

text_file.write_text(f"AUDIO: {orig_file.name}\n{text}")

return text_file

The Index for When Even Ripgrep Slows Down

Create a single SQLite FTS5 (full-text search) index:


import sqlite3

from pathlib import Path


def build_index():

db = sqlite3.connect(Path.home() / "brain.db")

db.execute("""

CREATE VIRTUAL TABLE IF NOT EXISTS brain_fts USING fts5(

path, content, timestamp,

tokenize='trigram'

)

""")

# Index all text files

for txt_file in Path.home().glob("brain/**/*.txt"):

content = txt_file.read_text()

timestamp = txt_file.stat().st_mtime

db.execute(

"INSERT OR REPLACE INTO brain_fts VALUES (?, ?, ?)",

(str(txt_file), content, timestamp)

)

db.commit()


# Search is now instant even at 10M entries

def search(query):

db = sqlite3.connect(Path.home() / "brain.db")

return db.execute("""

SELECT path, snippet(brain_fts, 1, '<', '>', '...', 20)

FROM brain_fts

WHERE content MATCH ?

ORDER BY rank

""", (query,)).fetchall()

def smart_filename(text, max_len=50):

# For code: extract function/class name

if "def " in text or "class " in text:

match = re.search(r'(def|class)\s+(\w+)', text)

if match:

return match.group(2)

# For errors: extract error type

if "error" in text.lower():

return re.sub(r'[^\w\s-]', '', text.split('\n')[0])[:max_len]

# For conversations: extract participant names

if "@" in text or "from:" in text.lower():

people = re.findall(r'@(\w+)|from:\s*(\w+)', text, re.I)

if people:

return f"conv-{'-'.join(set(p[0] or p[1] for p in people))}"

# Default: first sentence, cleaned

first = text.split('.')[0][:max_len]

return re.sub(r'[^\w\s-]', '', first).replace(' ', '-')

def process_diff(diff_text):

functions = re.findall(r'^[+-].*def (\w+)', diff_text, re.M)

files = re.findall(r'^diff --git a/(.*) b/', diff_text, re.M)

summary = f"Changed files: {', '.join(files)}\nFunctions: {', '.join(functions)}"

return summary + "\n\n" + diff_text
